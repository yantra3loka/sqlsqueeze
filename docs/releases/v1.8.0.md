A feature release for striped backups, one-command verify, and graceful
cancel. The Release suite passed 370 tests. Live SQL CI on this commit
passed for SQL Server Express on Windows and for SQL Server 2022 and 2025
on Ubuntu 22.04 and 24.04.

## New

- **Striped backups.** One backup can write several files at once, the same
  shape as `BACKUP ... TO DISK = ..., DISK = ...`. Name stripes
  `<db>_<type>_[copyonly_]<yyyyMMdd_HHmmss>_s<ii>of<nn>.bak.zst`.
  `Restore-SqlChain` groups a set across directories, restores it in index
  order, and fails if a stripe is missing. Copy-only sets stay out of the
  chain. `WITH FORMAT` is on by default; `db(noformat)` opts out.
  `db(name=...;stats=10)` sets the backup-set name and progress interval.
- **`--verify` on `backup` and `backup-all`.** The finished backup is
  checked against its manifest in the same command (hashes, no SQL Server).
  Exit `-1` if that check fails.
- **Graceful Ctrl-C.** The first press aborts the running backup or restore
  through the normal failure path: partial files are removed, and a
  `--kill-connections` restore is returned to MULTI_USER. A second press
  kills immediately. Cancelling a restore leaves the database RESTORING.
- **DBA guide.** The Pages runbook now covers stripes, `--verify`, Ctrl-C,
  streaming a backup straight to S3 or Azure versus backup-then-copy, and
  the `Restore-SqlChain -StopAt` rules below.

## Fixed

- **Point-in-time chains.** `restore-chain --stopat` keeps the latest full
  at or before that time, the latest differential in between, and the logs
  up through the first log taken after that time. `STOPAT` is sent on every
  log step. `Restore-SqlChain -StopAt` does the same cutoff from file time,
  and it errors without restoring when the plan has no log to stop in.
  `-StandbyFile` and `-NoRecovery` cannot be combined, and a blank
  `-StandbyFile` is rejected.
- **Invalid restore SQL is rejected up front.** `PARTIAL` is emitted once,
  `backuptype` and `restoretype` are case-insensitive, and contradictory
  `WITH` options throw (`CHECKSUM` with `NO_CHECKSUM`, `STOP_ON_ERROR`
  with `CONTINUE_AFTER_ERROR`, `RECOVERY` with `NORECOVERY`, `STANDBY`
  with `RECOVERY` or `NORECOVERY`). Empty `STANDBY` (including quoted
  blanks) and empty `MOVE` endpoints are rejected.
